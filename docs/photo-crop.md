# 推しの写真の調整（拡大・縮小・移動・回転して丸の範囲を決める）

推しの登録・編集で写真を選んだら、そのまま取り込まずに調整画面を出し、丸の枠に写す範囲を決めてから取り込む。
決定の出典は Discussion #128（依頼 Issue #127）。実装は epic `epic/photo-crop`（PR #130・#134・#136・#138・#142・#143）。
ループが仮に決めたこと（拡大の上限・文言・枠の大きさなど）は判断ログ Issue #131 にある。

> **Android 版の SPEC（`shariverse/oshikatsu-countdown-android` の `docs/SPEC.md`）には、まだこの仕様が書かれていない。**
> Discussion #128 の Q4 で「iOS だけ先に作り、Android の SPEC は後で合わせる」と決めたため、しばらく iOS と Android で挙動が違う。
> Android 版に移すときは、このファイルの「仕様」を SPEC に書き写す。

## 仕様

### 流れ

1. 推しの登録・編集（初回の導線の推しの登録も同じ部品）で「写真を選ぶ／写真を変える」から写真を選ぶ（`PhotosPicker`。写真ライブラリの権限は要らない）
2. 写真を読めたら調整画面を全画面で出す（iPad も全画面）
3. 「完了」で丸のプレビューを切り抜いた見た目にする。取り込むのは推しを保存したとき
4. 「やめる」では何も変えない（前の写真・プレビュー・保存する内容のまま）

### 調整画面

- iOS の連絡先の写真の調整に寄せる。黒い地に写真、丸の枠の外を暗くし、上に「やめる」「移動と拡大・縮小」「完了」。書体と色は出荷するテーマ（`AppTheme.jiraiGothic`）のダークの色
- 操作: ピンチで拡大・縮小、ドラッグで移動、2 本指のひねりで自由な角度の回転。3 つを同時に効かせ、拡大と回転は枠の中心を軸にする
- 補正: 操作の途中は枠の隅が一時的に空いてもよい。指を離したら（ジェスチャーが中断されたときも）、枠の隅が空かない範囲に寄せる（「視差効果を減らす」ではアニメーションしない）
  - 枠を覆う最小の拡大率は回転角で変わる: |cos θ| + |sin θ|（0°・90° で 1、45° で √2。1 は回転なしで写真の短い辺が枠にぴったり収まる大きさ）
  - 移動できる範囲は、枠の正方形を写真の上に戻したときの外接矩形が写真からはみ出さない範囲
- 拡大の上限: 切り抜く範囲の一辺が元の写真の **360px** を下回らない倍率まで（短い辺が 360px より小さい写真は、枠を覆う大きさより拡大できない）
- 枠の一辺: 写真を置く範囲の短い辺 − 左右 16pt ずつ、上限 560pt（iPad で広がりすぎないように）
- VoiceOver・ジェスチャーを使えない人向け: 写真を 1 つの要素（「調整中の写真」。値は拡大率と回転の角度）にし、上下のスワイプで拡大・縮小（1.25 倍ずつ）、カスタムアクションで「左に回す」「右に回す」（5° ずつ）「元に戻す」。位置を動かす操作は無い
- 大きな文字で上のバーが 1 行に収まらないときは、見出しをボタンの下に回し、それでも収まらなければボタンの文字を折り返す
- 文言は 12 言語（`Shared/Resources/Localizable.xcstrings`）

### 取り込み

- **正方形に切り抜いた画像だけを保存する**（Q2）。SwiftData のスキーマ（`OshiConSchemaV2`）は変えず、範囲（拡大率・位置・回転）も保存しない
- 一辺は min(切り抜く範囲の画素の一辺, **1440px**)。小さい写真は拡大しない
- 写真の向き（EXIF の Orientation）を画素に反映した上で切り抜く。JPEG の画質 0.85、位置情報などのメタデータは残さない（範囲なしの取り込みと同じ）
- 写真の色空間（Display P3 など）のまま切り抜く。HDR（ITU-R 2100）・extended range の色空間は Display P3 に落とす（トーンマッピングはしない）
- 大きな写真は、切り抜く範囲が 1440px より広ければ、切り抜いた結果に足りる大きさまで縮めて読んでから切り抜く。それより狭く切り抜く（強く拡大した）ときは、粗くしないよう元の大きさで読む（4800 万画素なら一時的に約 200MB。実機での確認は #135）
- 取り込み・縮小・切り抜きはメインアクターの外（`@concurrent`）で行う。調整画面で描く写真は、短い辺が枠の上限 × 画面の倍率になる大きさ（長辺は 4096px まで）に縮めて読む

### 表示

- 丸のアバター（ホームの行・推しの一覧など）は、正方形の画像をそのまま丸く出す
- 予定の詳細の横長の写真（画面の幅 × 300pt、横向きの iPhone は 140pt）は、**1 つの正方形の範囲を丸と詳細の両方に使う**（Q1）。今までどおり `scaledToFill` の中央基準なので、正方形の中央の帯が写る。
  詳細の写る範囲が今より狭くなり、拡大すると粗くなりやすいことは承知の上
- ウィジェットは写真を出さない（今までどおり）

### 既存の写真と、調整し直し

- この機能より前に登録した写真は、今の見え方（中央基準）のまま残す。勝手に切り抜き直さない（Q2）
- 写真があるときは「位置を調整」で調整画面を開き直せる
  - 保存してある写真: その JPEG（切り抜いた後の画像）から開く。保存してあるのは切り抜いた後の画像なので、**さらに狭める調整だけ**になる（Q2）。範囲を広げたいときは写真を選び直す。
    何も変えずに「完了」したら差し替えない（JPEG を書き直して画質を落とさない）
  - 保存する前に選んだばかりの写真: 元の選んだ写真と前の範囲から開き直す（前より広げ直すこともできる。「元に戻す」は前の範囲に戻る）
- 写真の差し替え・「写真を外す」・推しの削除で、使わなくなった写真のファイルを消す規則は今までどおり（`OshiEditing`）

### 作らないもの

- 元の写真と範囲を保存して何度でもやり直せる方式・スキーマの変更（Q2 で採らなかった）
- 丸と詳細で別々に範囲を決める調整（Q1 で採らなかった）
- 取り込む画像の解像度・画質を選ぶ機能、ウィジェットに写真を出すこと
- 権限・プライバシーマニフェストの追加、通信

## コードの場所

| 役割 | 場所 |
| --- | --- |
| 範囲の計算（拡大率・回転・位置 → 切り抜く正方形、補正、拡大の上限・下限、画面の枠への配置） | `OshiCon/Photo/PhotoCrop.swift`（`nonisolated struct PhotoCrop`） |
| 切り抜いて JPEG にする | `OshiCon/Photo/PhotoResizer.swift`（`croppedImage`・`croppedJPEGData`） |
| 写真の置き場所・取り込み・調整画面に渡す写真の読み込み | `OshiCon/Photo/OshiPhotoLibrary.swift`（`importPhoto(_:crop:)`・`cropSource`・`photoData`） |
| 調整画面と、画面から切り離した決まり（枠の大きさ・ジェスチャーの量・読み上げの操作） | `OshiCon/Photo/PhotoCropScreen.swift`（`PhotoCropScreen`・`PhotoCropLayout`・`PhotoCropGesture`・`PhotoCropAccessibility`） |
| 写真を選ぶ部品と導線（調整画面を出す・位置を調整） | `OshiCon/Photo/OshiPhotoPicker.swift` |
| 保存のときの取り込みと前の写真の削除 | `OshiCon/Photo/OshiEditing.swift`（`PhotoChange.replace(Data, crop:)`） |

座標は「向きを反映した後の元の写真の画素」で持ち、画面の pt との変換は `PhotoCrop.layout(frameSide:)`・`dragged(by:frameSide:)` の中だけで行う。
画面では写真の中心を枠の中心に置き、`scaleEffect` → `rotationEffect`（写真の中心を軸。y が下向きで正の角度は時計回り）→ `offset` の順で描く。
切り抜きの `CGContext` は y が上向きなので、同じ見た目にするには回転の符号を反転して描く。

## テスト

- Unit（Swift Testing）: `OshiConTests/Photo/` の `PhotoCropTests`（補正・上限・下限・角度・配置）、`PhotoResizerCropTests`（4 つの象限を色分けした画像で、拡大・移動・回転・EXIF の向き・1440px の上限・色空間など）、`PhotoCropScreenTests`（枠の大きさ・ジェスチャーの量・読み上げの操作・配色）、`OshiEditingTests`（範囲つきの保存）
- UI（XCTest）: `OshiConUITests/PhotoCropUITests`。`PhotosPicker` は別プロセスの画面で操作できないので、起動引数 `-useTestPhoto`（`LaunchOptions.usesTestPhoto`。`-useInMemoryStore` のときだけ効く）で、
  「写真を選ぶ」を生成した画像（`PhotoCropPreviewImage`。色と図形）を選ぶボタンに替えて、選ぶ → 調整 → 保存・やめる・位置を調整の導線を通す
- 実機での確認が要ること: #135（4800 万画素の取り込みの速さとメモリ）、#139（ピンチ・ひねり・中断・VoiceOver の操作、`PhotosPicker` を閉じても写真が外れないこと）
